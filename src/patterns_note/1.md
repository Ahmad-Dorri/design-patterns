# Pattern number one

Identify the aspects of your application that vary and separate them from what stays the same.

> details in the duck application:

In duck application we have some behaviors that some subclasses may have it, or not. Something like flying that a decoy duck can't fly and something like mallard duck can. We should separate these things that are vary from something like display method. The display method is for showing the model. So all models have this method. We can use inheritance for this method but something like quack sound or fly behavior is vary. We created two behavior interface and implement different type of those behaviors and use them inside each duck. With the help of setter we can change a class behavior in runtime on the fly.
